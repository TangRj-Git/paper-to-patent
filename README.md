# paper-to-patent 技能使用说明

更新时间：2026-05-13

适用对象：已经拿到 `paper-to-patent` skill 文件夹，并希望使用 Codex/大模型自动完成“小论文转发明专利”流程的实验室同学。

---

## 1. 这个 skill 是做什么的

`paper-to-patent` 用于辅助把小论文、技术报告、实验方案或模型方法说明转写为中国发明专利相关材料。

它可以辅助完成：

1. 判断小论文是否适合转发明专利。
2. 生成论文-专利内容映射表。
3. 生成当前小论文专属专利大纲。
4. 生成权利要求框架。
5. 生成发明专利正文 Markdown。
6. 检查正文是否严格来源于小论文。
7. 检查公式、术语、权利要求和说明书支撑关系。
8. 生成附图详细解析。
9. 按确认后的解析逐张生成 SVG 附图。
10. 在需要时逐张生成 PPT 可编辑图。
11. 检查最终 Word/PDF 中的内容、图文对应和元数据。

## 2. 安装方式

将整个 `paper-to-patent` 文件夹复制到自己的 Codex skills 目录中。

Windows 常见路径：

```text
C:\Users\你的用户名\.codex\skills\paper-to-patent
```

Linux 或 macOS 常见路径：

```text
~/.codex/skills/paper-to-patent
```

复制完成后，目录结构应类似：

```text
paper-to-patent/
  SKILL.md
  agents/
    openai.yaml
  references/
    小论文生成发明专利完整工作流程.md
    小论文转发明专利通用参考模板.md
```

安装后建议重启 Codex 或开启新会话，使 skill 被重新加载。

## 3. 如何触发使用

可以直接在对话里点名使用：

```text
请使用 paper-to-patent skill，根据这个小论文生成发明专利相关材料。
```

也可以用中文描述触发：

```text
请按照“小论文转发明专利”的流程，根据我提供的小论文生成专利可行性判断、论文-专利映射表、专属大纲、权利要求框架和发明专利正文 md。
```

如果有文件路径，建议直接给出：

```text
小论文路径是 formal/main.pdf，请使用 paper-to-patent skill 先进行专利可行性判断和论文-专利内容映射。
```

## 4. 推荐使用流程

不要一开始就要求大模型直接生成完整 Word 专利。建议按阶段使用。

### 4.1 第一步：可行性判断与映射

推荐提示词：

```text
请使用 paper-to-patent skill，先判断这篇小论文是否适合转写为发明专利，并生成论文-专利内容映射表和当前小论文专属专利大纲。暂时不要生成完整专利正文，也不要生成图片。
```

这一步建议产出：

1. `专利可行性判断报告.md`
2. `论文-专利内容映射表.md`
3. `当前小论文专属专利大纲.md`

### 4.2 第二步：生成权利要求框架

推荐提示词：

```text
根据刚才的论文-专利映射表和专属专利大纲，生成权利要求框架，重点包括方法权利要求、从属权利要求、系统权利要求、电子设备和计算机可读存储介质权利要求。
```

这一步建议产出：

1. `权利要求框架.md`

### 4.3 第三步：生成发明专利正文 md

推荐提示词：

```text
请根据论文-专利内容映射表、专属专利大纲和权利要求框架，生成发明专利正文 Markdown 文件。要求内容严格来源于小论文，公式和术语与小论文保持一致，暂时不要生成任何图片。
```

这一步建议产出：

1. `发明专利正文_初稿.md`
2. 或 `发明专利正文_严格来源论文版.md`

### 4.4 第四步：检查正文

推荐提示词：

```text
请详细检查发明专利正文 md，重点检查内容是否严格来源于小论文，公式是否一致，术语是否统一，权利要求是否有说明书支撑，以及是否存在论文式实验结果表述。
```

这一步建议产出：

1. `发明专利正文检查报告.md`
2. 修改后的正文 md

### 4.5 第五步：生成附图详细解析

正文确认无误后，再生成附图解析。

推荐提示词：

```text
现在正文内容已经确认无误。请根据发明专利正文生成附图详细解析 md，说明需要几张图、每张图对应正文哪一部分、图中应包含哪些模块、箭头如何连接、图中文字如何写。暂时不要生成 SVG。
```

这一步建议产出：

1. `发明专利附图详细解析.md`

### 4.6 第六步：逐张生成 SVG 图

必须一张一张生成，不建议一次生成所有图。

推荐提示词：

```text
请根据附图详细解析，先生成摘要附图 SVG。生成后请立即检查图中文字、箭头、模块名和正文对应关系。
```

确认后再继续：

```text
继续生成图1 SVG。
```

```text
继续生成图2 SVG。
```

每张图都应生成、检查、修改，确认无误后再进入下一张。

### 4.7 第七步：逐张生成 PPT 可编辑图

如果需要可编辑 PPT 图，再执行这一步。

推荐提示词：

```text
请根据已经确认无误的图1 SVG，生成对应的 PPT 可编辑绘制版。只生成这一张，生成后检查是否和 SVG 内容一致。
```

PPT 图也建议逐张生成。

### 4.8 第八步：人工导入 Word

建议人工将 Markdown 正文和 SVG/PPT 图导入 Word 模板中。

原因：

1. Word 自动生成容易出现乱码。
2. 公式上下标容易乱。
3. 人工导入更方便按官网格式调整。
4. 图号、分页、摘要附图和说明书附图更容易控制。

### 4.9 第九步：检查最终 PDF

Word 导出 PDF 后，可以再让大模型检查。

推荐提示词：

```text
请使用 paper-to-patent skill，详细检查这个发明专利 PDF：正文内容是否完整，摘要附图和图1至图N是否与正文对应，是否存在旧模板残留，PDF 元数据标题和作者是否正确，公式和图中文字是否正常。
```

---

## 5. 使用时要特别注意

1. 不要一开始就要求生成完整 Word。
2. 不要在正文没有确认前生成图片。
3. 不要一次生成所有 SVG 图。
4. 不要把论文实验结果表格直接写进专利。
5. 不要让大模型加入小论文没有支撑的新功能。
6. 公式必须逐个检查，尤其是上下标、变量含义和符号一致性。
7. 图中文字必须和正文术语一致。
8. 最终权利要求建议让导师或专利代理人把关。

## 6. 常用提示词汇总

### 6.1 完整启动提示词

```text
请使用 paper-to-patent skill，根据我提供的小论文生成发明专利相关材料。先只进行专利可行性判断、论文-专利内容映射和当前小论文专属专利大纲，不要生成正文和图片。
```

### 6.2 正文生成提示词

```text
请根据已经确认的映射表、大纲和权利要求框架，生成发明专利正文 md。要求内容严格来源于小论文，突出完整技术方案和实现流程，不写具体实验结果表格，暂时不要生成图片。
```

### 6.3 正文检查提示词

```text
请详细检查当前发明专利正文 md，重点检查来源一致性、公式一致性、术语一致性、权利要求支撑关系、专利话术和是否存在不应写入的论文实验结果。
```

### 6.4 附图解析提示词

```text
请根据已经确认的专利正文生成附图详细解析 md，说明每张图的作用、对应正文段落、图中模块、箭头连接、排版方式和检查标准。暂时不要生成 SVG。
```

### 6.5 单张 SVG 生成提示词

```text
请根据附图详细解析生成图1 SVG。只生成这一张图，并在生成后检查图中文字、箭头方向、模块名和正文对应关系。
```

### 6.6 PDF 终稿检查提示词

```text
请检查这个发明专利 PDF 是否可以作为终稿，重点检查正文、公式、图文对应、摘要附图、图1至图N、旧模板残留、PDF 元数据标题和作者。
```

---

## 7. 一句话使用原则

使用 `paper-to-patent` skill 时，按“先判断和映射、再写大纲和权利要求、再写正文、正文确认后再画图、最后检查 PDF”的顺序推进，不要跳过中间检查点。
