# 小论文转发明专利通用参考模板

整理时间：2026-05-12

与完整工作流程的关系：本文件主要提供“怎么写”的通用结构、模板、话术、公式要求、附图要求和自检清单；完整执行顺序、阶段产物、逐张制图流程、Word/PDF 终稿检查流程，见 `小论文生成发明专利完整工作流程.md`。

适用对象：实验室同学将已经完成或基本成稿的小论文、会议论文、项目技术报告、阶段性实验方案改写为中国发明专利申请文件时使用。

本文档目标：帮助作者快速把“论文式表达”转换为“专利式表达”，形成可继续交给导师或专利代理人员审查的初稿。本文档只提供内容组织、话术、逻辑和自检规则，不替代导师或专利代理人员的法律审查。

## 0. 官方依据与核心要求

### 0.1 核心要求

发明专利申请文件的核心要求可以概括为：

```text
说明书应当清楚、完整地描述发明，使所属技术领域的技术人员能够实现该发明；权利要求书应当以说明书为依据，清楚、简要地限定要求保护的范围。
```

因此，小论文转发明专利时，重点不是展示论文实验结果，而是写清楚：

1. 要解决什么技术问题。
2. 使用什么输入数据、部件、材料、信号或对象。
3. 按什么步骤进行处理。
4. 每一步产生什么中间结果。
5. 最终输出什么结果。
6. 输出结果用于什么技术目的。
7. 本领域技术人员是否能够按照说明书实施。

### 0.2 主要参考来源

1. 国家知识产权局《专利审查指南》：说明书和附图用于清楚、完整地描述发明，使本领域技术人员能够理解和实施；权利要求书用于限定保护范围。  
   https://www.cnipa.gov.cn/attach/0/da9d262dfdfa4b9d82910c98cc3b7cbd.pdf

2. 国家知识产权局关于算法类发明撰写要求：当权利要求包含算法特征时，应当把算法特征与具体技术领域结合，写清输入参数、输出结果以及整个解决技术问题的过程。  
   https://www.cnipa.gov.cn/art/2019/12/31/art_2073_143003.html

3. 国家知识产权局申请文件形式要求：说明书通常包括技术领域、背景技术、发明内容、附图说明、具体实施方式；摘要、附图、公式、权利要求也有对应的撰写和标记要求。  
   https://www.cnipa.gov.cn/art/2013/3/21/art_564_147418.html

### 0.3 对小论文转专利的直接启发

把小论文改写成发明专利时，应优先写以下内容：

1. 技术问题：写现有技术为什么不够，而不是写“我的实验效果很好”。
2. 完整实现流程：写成可以执行的步骤，而不是只描述模型思想。
3. 关键技术特征：突出本方案真正区别于现有技术的处理方式、结构、流程或参数关系。
4. 输入和输出：算法类、软件类和系统类专利尤其要写清输入是什么、输出是什么。
5. 公式和变量解释：公式要服务于步骤，每个变量都要解释，公式结果要说明用于哪个环节。
6. 有益效果：写技术效果，不写论文式排名、表格、具体数值和提升百分比。
7. 附图：图应该表达实现流程、模块关系或结构关系，不应主要展示论文实验结果。

### 0.4 通用写作边界

建议写：

```text
通过上述方式，能够为[预警/诊断/调度/控制/运维]提供依据。
```

谨慎写：

```text
自动执行[扩容/限流/迁移/控制]。
```

除非小论文已经完成并验证了对应闭环控制或执行过程，否则应写成“辅助依据”“辅助建议”或“参考信息”。

## 1. 使用范围

### 1.1 适合使用本模板的小论文

本模板主要适用于以下类型的小论文：

1. 工程技术类小论文。
2. 算法模型类小论文。
3. 软件系统类小论文。
4. 智能监测、预测、诊断、识别、调度、控制类小论文。
5. 工业互联网、智慧矿山、云边协同、微服务、物联网、数据分析、自动化系统等应用场景论文。
6. 已经有明确输入、处理流程、输出结果和技术效果的小论文。
7. 已经形成可执行算法、系统模块、实验平台、数据处理流程、模型训练流程或控制流程的小论文。

### 1.2 不适合直接套用本模板的小论文

以下类型不能直接照搬本模板，需要结合具体领域另行调整：

1. 纯理论分析、纯数学证明、纯综述类论文。
2. 只有实验现象或性能对比，但没有明确技术方案的论文。
3. 主要创新点是商业规则、管理方法、教学方法或组织流程的论文。
4. 只有未来设想，尚未形成可实施技术流程的论文。
5. 医疗、化学、生物、材料、机械结构等强领域专利；这些领域可以参考本文的结构和话术，但必须补充本领域专门写法。

### 1.3 使用原则

1. 专利必须写“技术方案”，不是写“论文总结”。
2. 专利重点是“别人能否照着实现”，不是“实验结果有多好”。
3. 专利可以比论文更偏保护范围，但不能脱离论文已有技术内容。
4. 论文中的具体实验结果、对比模型、提升百分比通常不放进专利正文。
5. 如果论文尚未发表，应优先确认专利申请和论文公开的先后顺序。

## 2. 小论文与发明专利的核心区别

### 2.1 小论文关注什么

小论文通常关注：

1. 研究背景。
2. 相关工作。
3. 方法创新。
4. 实验设置。
5. 对比结果。
6. 消融分析。
7. 结论和未来工作。

论文常见表达：

```text
本文提出...
实验结果表明...
与某方法相比提升...
消融实验验证...
```

### 2.2 发明专利关注什么

发明专利通常关注：

1. 技术领域。
2. 现有技术问题。
3. 要解决的技术问题。
4. 完整技术方案。
5. 可选实施方式。
6. 技术效果。
7. 权利要求保护范围。

专利常见表达：

```text
本申请提供一种...
所述方法包括...
在一些实施例中...
所述模块用于...
通过上述方式，能够...
```

### 2.3 转写原则

| 小论文内容 | 专利中应如何处理 |
|---|---|
| 研究背景 | 转写为背景技术 |
| 方法流程 | 转写为独立权利要求和具体实施方式 |
| 模型结构 | 转写为系统模块或算法处理单元 |
| 实验结果 | 一般不写，或仅作为示例性技术效果弱化描述 |
| 对比模型 | 一般不写入专利正文 |
| 消融分析 | 转写为有益效果或可选实施方式，不写具体数值 |
| 未来工作 | 不写成已经实现的技术特征 |
| 公式推导 | 转写为关键计算公式，并解释变量和作用 |

## 3. 内容写作简版流程

本节是从“通用模板怎么写”的角度给出的简版流程。若需要从小论文准备、公开风险检查、专属大纲、逐张制图、PPT 重绘到 PDF 终稿检查的完整 SOP，应使用 `小论文生成发明专利完整工作流程.md`。

### 3.1 第一步：从小论文提取技术方案

先不要直接写专利，先从小论文中提取以下内容：

```text
1. 技术领域：
2. 应用场景：
3. 现有技术问题：
4. 输入数据：
5. 核心处理流程：
6. 关键算法/模型/结构：
7. 输出结果：
8. 输出用途：
9. 训练/更新/控制流程：
10. 技术效果：
```

建议整理为表格：

| 提取项 | 从论文中提取的内容 | 是否可写入专利 | 备注 |
|---|---|---|---|
| 技术问题 |  | 是/否 |  |
| 输入数据 |  | 是/否 |  |
| 方法步骤 |  | 是/否 |  |
| 模型结构 |  | 是/否 |  |
| 输出结果 |  | 是/否 |  |
| 具体实验数值 |  | 通常否 | 可不写 |
| 未来工作 |  | 通常否 | 不写成已实现 |

### 3.2 第二步：确定独立权利要求

独立权利要求决定保护范围，建议先写权利要求1，再写说明书。

权利要求1应回答：

1. 这个方法处理什么对象？
2. 输入是什么？
3. 核心处理步骤是什么？
4. 输出是什么？
5. 输出用于什么技术目的？

### 3.3 第三步：补充从属权利要求

从属权利要求用于限定关键细节：

1. 输入数据包括哪些。
2. 预处理如何进行。
3. 特征如何构建。
4. 模型或算法如何计算。
5. 参数或阈值如何设置。
6. 训练或优化如何进行。
7. 输出如何应用。

### 3.4 第四步：写系统/装置权利要求

将方法步骤转换为模块：

```text
数据获取模块
预处理模块
特征构建模块
核心处理模块
结果输出模块
训练/更新模块
```

### 3.5 第五步：写说明书

说明书按以下顺序写：

```text
技术领域
背景技术
发明内容
附图说明
具体实施方式
```

### 3.6 第六步：最后写摘要和画图

摘要最后写，原因是摘要要与权利要求和说明书一致。

附图根据权利要求和具体实施方式确定，不要直接搬论文实验图。

## 4. 发明专利文件通用结构

一份发明专利通常包含：

1. 说明书摘要。
2. 摘要附图。
3. 权利要求书。
4. 说明书。
5. 说明书附图。

说明书通常包含：

1. 技术领域。
2. 背景技术。
3. 发明内容。
4. 附图说明。
5. 具体实施方式。

推荐写作顺序：

```text
先写权利要求1
  -> 写从属权利要求
  -> 写系统/装置/设备/介质权利要求
  -> 写说明书发明内容
  -> 写具体实施方式
  -> 写背景技术
  -> 写摘要
  -> 整理附图
```

## 5. 发明名称通用模板

### 5.1 常用命名结构

```text
一种[应用场景]的[技术目标]方法及系统
```

```text
一种基于[核心技术特征]的[对象]处理方法及系统
```

```text
[对象]的[处理目标]方法、装置、设备及介质
```

```text
一种[对象]的[预测/识别/诊断/调度/控制/优化]方法及系统
```

### 5.2 命名建议

1. 名称中体现应用对象。
2. 名称中体现技术目标。
3. 名称不宜塞入过多细节。
4. 名称不要写具体实验平台、数据集、样本数量。
5. 如果是软件算法类，可用“方法及系统”或“方法、装置、设备及介质”。

### 5.3 示例

```text
一种工业设备故障诊断方法及系统
```

```text
一种基于多源数据融合的设备状态预测方法及系统
```

```text
一种云边协同环境下的任务调度方法、装置、设备及介质
```

```text
一种面向微服务系统的性能预测方法及系统
```

## 6. 说明书摘要通用模板

### 6.1 摘要功能

摘要用于简要说明：

1. 本发明属于什么技术领域。
2. 本发明做了什么。
3. 本发明的核心步骤是什么。
4. 本发明产生什么技术效果。

摘要不适合写：

1. 大量背景。
2. 具体实验数值。
3. 对比模型名称。
4. 提升百分比。
5. 复杂公式。

### 6.2 摘要通用模板

```text
本申请公开了一种[发明名称]，涉及[技术领域]。该方法包括：获取[目标对象]的[输入数据]；根据所述[输入数据]构建[中间数据/特征/状态]；对所述[中间数据/特征/状态]进行[核心处理]，得到[处理结果]；基于所述[处理结果]生成[输出结果]；将所述[输出结果]提供给[应用模块/应用场景]。通过上述方式，本申请能够[技术效果1]，并为[技术效果2]提供依据。
```

### 6.3 摘要示例

```text
本申请公开了一种设备状态预测方法及系统，涉及工业设备智能运维技术领域。该方法包括：获取目标设备的运行监测数据；根据所述运行监测数据构建设备状态特征序列；对所述设备状态特征序列进行时序编码，得到设备状态表示；基于所述设备状态表示输出未来时刻的状态预测结果；将所述状态预测结果提供给监测平台或预警模块。通过上述方式，本申请能够提高设备状态变化的预测能力，为故障预警和运维决策提供预测依据。
```

### 6.4 摘要自检

1. 是否控制在约300字以内。
2. 是否没有写实验结果和提升百分比。
3. 是否能对应权利要求1的核心步骤。
4. 是否没有出现论文式“本文提出”。
5. 是否落到明确技术效果。

## 7. 权利要求书通用模板

### 7.1 方法独立权利要求模板

```text
1. 一种[应用场景]的[技术目标]方法，其特征在于，包括：

获取[目标对象]的[输入数据]；

根据所述[输入数据]构建[第一中间数据/第一特征/第一状态]；

根据所述[输入数据]或所述[第一中间数据]构建[第二中间数据/第二特征/第二状态]；

对所述[第一中间数据]和/或所述[第二中间数据]进行[核心算法/模型/规则/控制]处理，得到[处理结果]；

基于所述[处理结果]生成[输出结果]；

将所述[输出结果]提供给[应用模块/执行模块/预警模块/控制模块/调度模块]。
```

### 7.2 从属权利要求模板

输入数据限定：

```text
2. 根据权利要求1所述的方法，其特征在于，所述[输入数据]包括[数据1]、[数据2]、[数据3]和[数据4]中的至少一种。
```

预处理限定：

```text
3. 根据权利要求1所述的方法，其特征在于，所述根据所述[输入数据]构建[中间数据]，包括：对所述[输入数据]进行时间对齐、缺失值处理、归一化处理和特征提取中的至少一种。
```

核心算法限定：

```text
4. 根据权利要求1所述的方法，其特征在于，所述[核心处理]包括：[步骤A]、[步骤B]和[步骤C]。
```

输出限定：

```text
5. 根据权利要求1所述的方法，其特征在于，所述[输出结果]包括[结果1]、[结果2]和[结果3]中的至少一种。
```

训练或优化限定：

```text
6. 根据权利要求1所述的方法，其特征在于，所述方法还包括模型训练步骤，所述模型训练步骤包括：基于训练样本构建损失函数，并根据所述损失函数优化模型参数。
```

结果应用限定：

```text
7. 根据权利要求1所述的方法，其特征在于，所述将所述[输出结果]提供给[应用模块]，包括：根据所述[输出结果]生成预警信息、状态评估信息、控制辅助建议或调度辅助建议。
```

### 7.3 系统/装置权利要求模板

```text
一种[应用场景]的[技术目标]系统，其特征在于，包括：

数据获取模块，用于获取[目标对象]的[输入数据]；

数据处理模块，用于对所述[输入数据]进行预处理，得到[预处理结果]；

特征构建模块，用于根据所述[预处理结果]构建[特征/序列/状态]；

核心处理模块，用于对所述[特征/序列/状态]进行[核心处理]，得到[处理结果]；

结果输出模块，用于基于所述[处理结果]输出[输出结果]；

应用模块，用于根据所述[输出结果]生成[应用信息/控制建议/预警信息/调度建议]。
```

### 7.4 电子设备和存储介质模板

软件、算法、数据处理、控制系统类专利通常可以补充：

```text
一种电子设备，包括处理器和存储器，所述存储器存储有计算机程序，其特征在于，所述处理器执行所述计算机程序时实现权利要求1至N中任一项所述的方法。
```

```text
一种计算机可读存储介质，其上存储有计算机程序，其特征在于，所述计算机程序被处理器执行时实现权利要求1至N中任一项所述的方法。
```

注意：

1. 这两项不是必须，但软件算法类专利通常建议保留。
2. 它们是方法的软件实现载体，不代表必须发明一台新硬件。
3. 如果导师或代理人要求精简，可删除或调整。

### 7.5 权利要求注意事项

1. 独立权利要求写核心闭环，不要写太多实验细节。
2. 从属权利要求逐层限定，不要重复整段独立权利要求。
3. 关键创新点必须进入权利要求。
4. 不要在权利要求里写“实验表明”“效果最好”“精度最高”。
5. 不要把未验证的未来工作写入权利要求。
6. 尽量使用“至少一种”“一个或多个”“预设”“可选地”等保留范围。

## 8. 说明书通用模板

### 8.1 技术领域

模板：

```text
[0001] 本申请涉及[一级技术领域]，具体涉及一种[发明名称]。
```

示例：

```text
[0001] 本申请涉及工业设备智能运维技术领域，具体涉及一种设备状态预测方法及系统。
```

要求：

1. 简短。
2. 不展开背景。
3. 与发明名称一致。

### 8.2 背景技术

推荐逻辑：

```text
行业或应用场景发展
  -> 现有技术通常怎么做
  -> 现有技术存在什么不足
  -> 因此需要新的技术方案
```

模板：

```text
[0002] 随着[应用场景]的发展，[目标系统/目标对象]在[业务场景]中被广泛应用。

[0003] 现有方法通常通过[现有技术方式]实现[技术目标]。

[0004] 然而，在[复杂条件/特殊场景]下，现有方法存在[问题1]、[问题2]和[问题3]，导致[不良后果]。

[0005] 因此，亟需一种能够[解决方向]的技术方案。
```

注意：

1. 背景技术不要写自己的完整方案。
2. 背景技术不要写实验结果。
3. 背景问题要能被后文技术方案回应。

### 8.3 发明内容

模板：

```text
[0006] 本申请提供一种[发明名称]，旨在解决现有技术中[问题1]、[问题2]和[问题3]的问题。

[0007] 第一方面，本申请实施例提供一种[方法名称]，所述方法包括：

[0008] 获取...
[0009] 根据...
[0010] 对...
[0011] 基于...
[0012] 将...

[0013] 第二方面，本申请实施例提供一种[系统/装置名称]，所述系统包括...

[0014] 第三方面，本申请实施例提供一种电子设备...

[0015] 第四方面，本申请实施例提供一种计算机可读存储介质...

[0016] 本申请实施例提供的技术方案至少具有以下有益效果：
第一，...
第二，...
第三，...
```

有益效果写法：

```text
通过[技术特征]，能够[技术效果]。
```

不要写：

```text
实验结果证明本方法最好。
```

### 8.4 附图说明

模板：

```text
[0020] 图1为本申请实施例提供的一种[整体方法流程]示意图。
[0021] 图2为本申请实施例提供的一种[数据处理流程]示意图。
[0022] 图3为本申请实施例提供的一种[核心模型/系统结构]示意图。
[0023] 图4为本申请实施例提供的一种[训练/控制/决策流程]示意图。
[0024] 图5为本申请实施例提供的一种[系统/装置模块]结构示意图。
```

要求：

1. 附图说明只列图名，不展开细节。
2. 图名要和正文引用一致。
3. 图的顺序要和具体实施方式出现顺序一致。

### 8.5 具体实施方式

开头模板：

```text
[0025] 以下结合附图对本申请的示范性实施例进行说明。应当理解，所描述的实施例仅用于说明本申请的技术方案，并不构成对本申请保护范围的限定。
```

步骤模板：

```text
[0026] 请参见图1，图1为本申请实施例提供的一种[方法名称]的整体流程示意图。该方法可以包括步骤101至步骤10N。

[0027] 步骤101，获取...
[0028] 步骤102，构建...
[0029] 步骤103，处理...
[0030] 步骤104，输出...
```

可选实施方式模板：

```text

```


## 9. 附图通用要求

### 9.1 推荐附图类型

1. 整体方法流程图。
2. 数据处理流程图。
3. 核心算法或模型结构图。
4. 训练、控制或决策流程图。
5. 系统或装置模块图。
6. 硬件结构图或部件连接图。
7. 工艺流程图。

### 9.2 不推荐作为专利附图的内容

1. 论文实验结果柱状图。
2. 模型对比折线图。
3. 消融实验图。
4. 复杂热力图。
5. 截图式界面图，除非界面本身是创新点。
6. 装饰性架构图。

### 9.3 附图自检

1. 每张图是否在附图说明中列出。
2. 每张图是否在具体实施方式中引用。
3. 图中编号是否和正文步骤一致。
4. 图中模块名称是否和权利要求一致。
5. 图中是否没有实验结果。
6. 图中文字是否足够简洁。

## 10. 公式通用要求

### 10.1 公式写法原则

1. 公式必须服务于技术步骤。
2. 公式前说明计算目的。
3. 公式后解释所有变量。
4. 公式后说明该计算结果如何使用。
5. 同一符号全文含义保持一致。
6. 预测值、估计值、真实值要区分。

### 10.2 公式引入话术

```text
在一种实施方式中，所述[结果]可以通过如下公式计算：
```

```text
所述[变量]满足如下关系：
```

```text
基于[输入]，通过如下公式得到[输出]：
```

```text
其中，[符号1]表示...，[符号2]表示...。
```

### 10.3 常见公式类型

序列构建：

```text
X_t=[x_{t-T+1},...,x_t]
```

融合：

```text
h=\alpha h_1+(1-\alpha)h_2
```

预测：

```text
\hat{y}_{t+h}=f_\theta(X_t)
```

残差预测：

```text
\hat{y}_{t+h}=y_t+\Delta \hat{y}_{t+h}
```

损失函数：

```text
L=w_1L_1+w_2L_2+\lambda L_c
```

阈值判断：

```text
当R_t大于预设阈值时，输出预警信息。
```

### 10.4 公式常见错误

1. 没解释变量。
2. 没说明公式用于哪个步骤。
3. 预测值和真实值符号混用。
4. 同一符号前后含义不一致。
5. 公式与权利要求脱节。
6. 把论文中的长推导全部搬进专利。

## 11. 常用专利话术库

### 11.1 数据获取

```text
获取目标系统中各对象的运行数据。
```

```text

```

```text
通过监测组件、传感器、网关或数据采集模块获取输入数据。
```

### 11.2 数据处理

```text
对所述输入数据进行时间对齐、归一化、特征提取和异常值处理中的至少一种。
```


```text
根据所述目标对象对应的多个数据源构建聚合特征。
```

### 11.3 核心处理

```text
将所述特征序列输入预测模型，得到状态表示。
```

```text
对所述第一特征和所述第二特征进行融合，得到融合表示。
```

```text
基于所述融合表示生成预测结果。
```

### 11.4 输出应用

```text
将所述预测结果提供给监控平台、预警模块或调度辅助模块。
```

## 12. 不同类型小论文的专利改写重点

### 12.1 算法模型类

重点写：

1. 输入数据。
2. 特征构建。
3. 模型结构。
4. 前向计算流程。
5. 训练损失。
6. 输出结果。
7. 应用场景。

注意：

1. 不要只写模型名字。
2. 不要只写实验结果。
3. 要写清模型输入、处理和输出。

### 12.2 软件系统类

重点写：

1. 系统模块。
2. 模块之间的数据流。
3. 每个模块的功能。
4. 系统执行流程。
5. 输出结果和应用方式。

注意：

1. 系统模块要与方法步骤对应。
2. 不要只写软件界面。
3. 可以补充电子设备和存储介质权利要求。

### 12.3 检测诊断类

重点写：

1. 信号或数据采集。
2. 预处理。
3. 特征提取。
4. 状态识别或故障判别。
5. 诊断结果输出。
6. 预警或维护建议。

### 12.4 预测预警类

重点写：

1. 历史数据构建。
2. 预测模型。
3. 预测目标。
4. 预测视界。
5. 预测结果输出。
6. 预警或决策辅助。

注意：

1. 预测结果一般写成“提供依据”。
2. 不要把预测写成已经完成自动控制。

### 12.5 调度优化类

重点写：

1. 调度对象。
2. 约束条件。
3. 目标函数。
4. 候选方案生成。
5. 方案评价。
6. 调度方案输出。

注意：

1. 如果论文只做离线优化，不要写成在线闭环调度。
2. 约束条件和目标函数要解释变量。

### 12.6 控制方法类

重点写：

1. 状态采集。
2. 状态判断。
3. 控制策略生成。
4. 控制指令输出。
5. 执行反馈。

注意：

1. 如果小论文没有执行控制实验，不要写成实际执行控制。
2. 可以写“控制辅助建议”或“控制参数推荐”。

### 12.7 机械结构类

重点写：

1. 部件组成。
2. 部件连接关系。
3. 工作过程。
4. 结构带来的技术效果。

注意：

1. 不能只写功能，要写结构。
2. 附图必须清楚表达部件关系。

### 12.8 材料/工艺类

重点写：

1. 原料组成。
2. 配比范围。
3. 制备步骤。
4. 工艺条件。
5. 产物性能。

注意：

1. 配比和工艺范围要谨慎。
2. 需要结合领域专门写法。

## 13. 小论文转专利内容取舍规则

### 13.1 可以写入专利的内容

1. 技术问题。
2. 技术方案。
3. 数据处理流程。
4. 模型结构。
5. 系统模块。
6. 控制流程。
7. 训练或优化方法。
8. 输出结果类型。
9. 技术效果。

### 13.2 不建议写入专利的内容

1. 具体论文页码。
2. 具体实验样本数量。
3. 具体对比模型排名。
4. 具体提升百分比。
5. 具体随机种子。
6. 具体开发环境版本。
7. 论文未来工作。
8. 没有验证的扩展场景。

### 13.3 需要弱化的内容

论文写：

```text
实验结果表明，本方法优于所有对比模型。
```

专利改：

```text
通过上述方式，能够提高目标场景下的处理准确性和稳定性。
```

论文写：

```text
未来将开展在线控制。
```

专利不宜写成：

```text
本方法执行在线控制。
```

可改为：

```text
本方法能够为后续控制或调度提供辅助依据。
```

## 14. 通用自检清单

### 14.1 权利要求自检

1. 权利要求1是否覆盖完整技术闭环。
2. 核心创新点是否进入权利要求1。
3. 从属权利要求是否逐层限定。
4. 系统权利要求是否与方法步骤对应。
5. 是否避免写入具体实验结果。
6. 是否避免写入未实现的未来工作。
7. 是否避免把保护范围写得过窄。

### 14.2 说明书自检

1. 技术领域是否简洁。
2. 背景技术是否只写现有问题。
3. 发明内容是否对应权利要求。
4. 有益效果是否对应具体技术特征。
5. 具体实施方式是否能让本领域技术人员实现。
6. 术语是否前后一致。
7. 是否没有论文式“本文提出”。

### 14.3 附图自检

1. 是否每张图都有附图说明。
2. 是否每张图都在正文中引用。
3. 图中编号是否与正文一致。
4. 图中模块名称是否与权利要求一致。
5. 是否没有实验结果图。

### 14.4 公式自检

1. 公式是否解释变量。
2. 公式是否说明技术作用。
3. 预测值和真实值是否区分。
4. 同一符号是否含义一致。
5. 损失函数、阈值、权重是否说明用途。

### 14.5 来源一致性自检

1. 专利核心技术是否来自小论文。
2. 是否没有把论文未来工作写成已实现。
3. 是否没有加入小论文完全没有支撑的新模块。
4. 是否没有把离线实验写成在线部署。
5. 是否保留了论文中的主要技术术语。

## 16. 最终提醒

1. 专利不是论文压缩版，而是技术方案保护文件。
2. 先写权利要求，再写说明书，最后写摘要。
3. 小论文中的实验结果通常不需要写进专利。
4. 重点写完整实现流程、模块关系、输入输出和技术效果。
5. 任何“未来工作”不要写成已经实现。
6. 提交前必须确认论文和专利的公开顺序。
7. 最终权利要求建议让导师或专利代理人员把关。
