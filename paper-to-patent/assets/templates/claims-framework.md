# 权利要求框架

> 输出文件：`draft/internal/权利要求框架.md` 或作为 `权利要求书.md` 起草前的中间稿。
> 用途：先确定保护对象和层级，避免一次性生成不准确的完整权利要求书。

## 1. 保护对象选择

| 类型 | 是否采用 | 来源依据 | 备注 |
|---|---:|---|---|
| 方法 |  | 论文方法流程、算法步骤、处理流程 | 通常作为第一独立权利要求 |
| 系统/装置 |  | 论文系统架构、模型模块、实验平台结构 | 可对应方法步骤模块化 |
| 电子设备 |  | 软件算法类发明常用兜底保护 | 可选 |
| 计算机可读存储介质 |  | 软件算法类发明常用兜底保护 | 可选 |
| 计算机程序产品 |  | 仅在确有需要时采用 | 待确认 |

## 2. 方法独立权利要求

1. 一种[发明名称]，其特征在于，包括：

   获取[输入对象]；

   根据所述[输入对象]构建[中间表示]；

   对所述[中间表示]执行[核心处理]，得到[处理结果]；

   基于所述[处理结果]生成[输出结果]；

   将所述[输出结果]用于[应用场景]。

| 中间表示组 | 4-5 | 序列、特征、图、状态、向量构建方式 |  |
| 核心处理组 | 6-8 | 模型结构、算法流程、融合方式、约束函数 |  |
| 输出应用组 | 9-10 | 预测、检测、调度、预警、控制等输出 |  |
| 训练或优化组 | 11-12 | 损失函数、参数更新、搜索策略 |  |
